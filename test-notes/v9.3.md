# WVC v9.3 test notes

Artifact: `WVC-v9.3.zip`, SHA-256 `6683a1e33f7d9be0dc2637e32af9263f85629cc263e14194db8dc60f5fe1a004` (tested as `WVC-v9.3-test2.zip`, same file).
Changes from v9.2: `wvc-lib.sh` (language), `service.sh` (language read again after boot), `wvc-update.sh` (retry), `module.prop`. `wvc-fetch.dex` is unchanged (SHA-256 `b0dfaa71aa969f727a73ae7b671796323b188d551421d6ed9171c76848041ebe`).

## Findings that led to v9.3

| Test | Result |
|---|---|

| One-off script in `/data/adb/service.d/` running `wvc-fetch.dex` in the boot script context (`uid 0`, `u:r:magisk:s0`) | `boot_completed` at uptime 51 s. At +0 s: `UnknownHostException`. At +30, +60, +120, +300, +600 s: GitHub reached. The default network changed between +30 and +60 s (Wi-Fi and Ethernet both connected) |

| 1 | test 1 | Install over v9.2 from the root manager | Installer in Turkish (`Lordify WebView Changer'dan esinlenildi`, `Kontrol:`, `Kuruldu: 156.0.8078.47.0`) |
| 2 | test 1 | Reboot, `update.log` | Vanadium, AOSmium, Cromite and AnyWebView up to date: the check reached GitHub and Codeberg. The log was in English: `service.sh` read the language before `boot_completed`, when `settings` does not answer |
| 3 | test 2 | Install over test 1, reboot, `update.log` | Installer in Turkish; `update.log` in Turkish (`Vanadium: 156.0.8078.47.0 güncel (son: 156.0.8078.47.0)`), all four packages up to date |

Bench tests with busybox ash and stub `settings`/`getprop`: Settings list `tr-TR` with `en-US` properties gives Turkish; `en-US,tr-TR` gives English (the first language in the list counts); `null` falls back to `persist.sys.locale`, then `ro.product.locale`. Retry loop with a stub check: three failures then success give waits of 300, 300, 300, 3600 s; continuous failure gives 300 s six times, then 3600 s.

## Not tested

- Which retry reached the network in row 2 and row 3 (the log keeps only the last check).
- Magisk and tucana with v9.3; the changes are in shared shell code that ran on both with v9.2.
- Everything listed under "Not tested" in the v9.2 notes. KernelSU, added after the release: on MuMu Player (Android 15, x86_64, KernelSU 3.2.5 GKI) `test/bildirim-test.sh` and `test/fetch-test.sh` gave the same results as on Magisk and FolkPatch: `su 2000 -c` posts the notification as `com.android.shell`, root and uid 1000 do not, and `wvc-fetch.dex` runs through `app_process` with the same certificate checks. The module itself was not installed there: none of the three providers publishes an x86_64 WebView in its current release.
