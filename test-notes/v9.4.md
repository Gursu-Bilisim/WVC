# WVC v9.4 test notes

Artifact: `WVC-v9.4.zip`, SHA-256 `d915de481d3a4ba9394d5e8cd2c65a08618079d7e3a007e46571160a7b9d3315` (tested as `WVC-v9.4-test5.zip`, same file).
Changes from v9.3: `customize.sh` (x86/x64, identical APK skipped, check for other WebView Changer modules without `grep -i`), `wvc-lib.sh` (ABI check by architecture family), `wvc-update.sh` (per-process temporary files, `module.prop` replaced with `mv`), `module.prop`. `wvc-fetch.dex` is unchanged (SHA-256 `b0dfaa71aa969f727a73ae7b671796323b188d551421d6ed9171c76848041ebe`).

Bench tests with busybox ash: three processes writing the module description 300 times each at the same time. The v9.3 code left `module.prop` with only the description line (as in row 4); per-process names with `cat >` still left 2 of 7 lines; the v9.4 code kept all 7 lines in three runs. The new matcher for other WebView Changer modules gave the same answers as `grep -qiE` on five sample files (no trailing newline, lower and upper case, the name only in `description=`, `WebViewChanger` without a space, emoji and Turkish letters).

## Not tested

- On x86_64, a fresh install of a WebView that is not installed yet: none of the three providers' current releases has an x86_64 WebView.
- The system install action with Magisk and KernelSU (no package needed it on jackpotlte and MuMu).
- Installing an update over a package that the Action button moved to the system.
- Skipping an identical APK on ARM devices (every ARM run started from a reset device).
